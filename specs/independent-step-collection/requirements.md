### 极简导航与原版差异基线（2026-09-21）

被试端主路径收敛为“首次身份 → 选择戒指 → 唯一首页 → 同一采集页 → 同一收尾页 → 首页记录”。搜索中、无结果和候选列表在选择戒指页原位切换；正在开始、正在采集和正在结束复用采集页；参考读数、异常读数和三种收尾复用收尾页。下载与上传在首页当前任务或记录卡中更新，不单独占用错误页面。

原版差异采用持续登记门禁：实现前先在 `change-review.md` 记录原版行为、当前行为、改变依据、数据影响、验证证据及差异类别；应恢复项优先对齐，已确认变化按新规格实现，证据不足项原则上沿用原版并继续取证。当前代码已经偏离原版的证据不足项不得视为通过，也不得继续扩大差异。每轮汇报主动列出本次新增或仍存在的原版差异。

- 首页同时呈现当前本地显示身份、佩戴位置、戒指连接状态、走路/跑步选择和最近记录。设备条件未满足时只显示具体恢复动作；加载文字不做成禁用按钮。
- 用户可随时离开界面。进行中的采集、下载和允许自动上传的任务继续由服务管理；返回后恢复同一session。身份与戒指管理入口始终可见；采集服务仍持有连接、设备检查、旧记录保全、下载或保存owner时，管理页只提供返回当前任务，释放owner后才允许更换身份或戒指。
- 设备行使用一个权威状态：BLE已连接只表示链路建立，完整STATUS/LIST核对通过后才显示“可以开始”。同屏不同时出现“已连接”和“尚未就绪”两种结论；每个阻断状态提供一个已实现的恢复动作。
- 冷启动读取持久资料期间显示中性加载态，读取完成后一次进入登记或首页，避免已有用户短暂看到空登记表。重复设置入口合并；busy时管理信息保持只读可见，不用隐藏入口表达锁定。
- 记录入口可查看全部本地和已上传记录，提供重传与脱敏导出；查看本地记录和手动上传不以BLE权限或采集owner启动为前置。删除本地原始记录须先明确云端回执、导出保全和其他session隔离，证据充分后再开放。
- 原版0.5.3要求每段选择左右手的食指、中指或无名指，并将手和手指写入上传包。独立版继续保留六种位置及session快照，采用首次选择后记住、需要时修改，减少重复操作。
- 原版0.5.3分别保存3–24位字母或数字用户名与服务端分配的研究身份，并允许空闲时切换用户。独立版登记时显式选择“研究编号”或“本地名称”：研究编号规范化后作为研究身份；本地名称无论字符形式均生成本机匿名ID。显示名称不写入研究包、CSV或云盘路径。当前同一安装内相同姓名会映射到同一匿名ID，换机或重装又会产生新ID；正式实验先使用研究编号，姓名身份须补可审计的唯一映射后才支持同名或跨设备识别。
- 更换身份会清除当前准备中的戒指与佩戴选择，随后重新选择；installation UUID和历史session保持。更换身份、位置或戒指只作用于之后的新session，已有session继续使用创建时冻结的准备快照。
- 原版的BLE串行队列、START/STOP/STATUS、Flash下载和恢复能力继续作为实现参考。独立版有意变化包括本地匿名身份、走路/跑步两段独立采集、外部计步器参考、三种收尾及独立后台上传；每项差异分别保留契约和验证证据。
- 可由程序判断的连接、查询、开始确认、停止确认、下载校验和上传恢复在后台有限重试。用户只看到当前任务和可执行动作。资料损坏优先从上一完整副本恢复；无法恢复时隔离损坏文件并重新登记，历史记录不删除。
- 戒指正在采集而手机没有对应本地账本时，保持记录归属未知，提供保全后停止、继续核对或导出入口；在研究身份规则确认前不自动归入当前被试，也不把用户留在没有动作的恢复页。
- 正式独立版只注册并运行新的采集与上传服务；旧`RingCaptureService`、`UploadJobService`及旧账本留作源码参考，不进入可启动的正式包。构建检查须证明旧服务不可解析、唯一BLE owner和版本化上传路径成立。
- 上传目标由被忽略的受控本地配置注入。正式APK核验目标存在且仓库无明文；无配置版本完整保存本地文件，显示手动上传条件，不显示成功状态。

## 1. 本功能边界与当前事实

统一流程是“选择走路或跑步 → 清零并开始 → 活动 → 停止确认 → 选择收尾方式”。每段重新选择，无默认活动；切换活动需先完成本段保存或明确放弃，再清零建立另一session。历史自由活动记录保留原契约，活动选择表示session任务声明，逐样本标签仍为未标注。

### 分段与收尾（2026-09-20）

- STOP确认及证据落盘后自动进入收尾页，突出“保存并上传”，并提供“保存，稍后上传”“放弃本段”。返回或重开依据持久任务恢复当前进度。
- 两种保存选择先持久保存上传意愿，再填写参考。有效0、缺失和不可靠参考沿用现有规则；读数可靠保存后才下载、校验原始文件。手机文件完整即允许回首页；后台上传与下一段采集独立。
- 收尾时提供简短、可选的本段异常说明，独立记录误混其他活动、额外休息、佩戴中断等事件。该说明与计步器读数质量原因分开保存、上传和导入，空白不影响正常保存。
- 稍后上传是持久策略。启动恢复、手机重启、联网、后台扫描、队列执行均尊重该策略；记录列表显示“稍后上传”和明确“上传”入口，用户主动操作后才允许排队。历史记录默认沿用原自动上传策略，原冻结ZIP保持不变。
- 放弃只作用于已确认停止、尚未尝试上传的当前段。二次确认取消保持原任务；确认先可靠保存放弃标记，再取消本段任务并按白名单清理手机文件。删除中断后继续同一清理，放弃段不生成实验包、不进入统计；其他session、参考、原始文件和回执保持不变。已放弃记录按保存的设备指纹排除重取，不因`unix_ms=0`或跨连接直接锁住戒指；开始仍须基于同次连接的完整、一致STATUS/LIST建立新段证据。
- 原SDK只有HEALTH START/STOP/STATUS/READ/LIST；原Android的discard仅删除手机任务，未提供戒指单段擦除。确认文案明确戒指原始记录保留。已放弃记录继续留在戒指时，App不把它归入新session；固件自然覆盖旧记录时允许旧基线从LIST消失，陌生新增或替换其他受保护记录仍拒绝。整个戒指清空和试发START不属于放弃操作。
- 普通断线、超时、空间不足和未校准日期应提供具体重试/继续入口。确实无法确认记录归属或本地文件损坏时保留数据并说明恢复条件；这些证据不足的情形不能以清空数据换取成功状态。

STOP目标时序以原版Android 0.5.3为准：命令发出后约500ms只查STATUS；仍在采集时每约1000ms继续查询STATUS；首次观察到stopped后等待约5000ms，再查询LIST；LIST尚未出现时每约2000ms重查，最多30次。当前工作区已按此顺序实现，并保存STOP命令入队、停止来源、高水位和重复回复证据；软件回归覆盖持续collecting、记录迟到、重开和不重复STOP。真实Flash尾部增长、断线、进程／整机恢复及持续重连仍按plan做真机验收。

既有Flash记录只作为开始前基线，不自动归入当前被试。当前软件允许多条旧记录、`unix_ms=0`记录和已放弃记录留在戒指；同次连接的完整、一致STATUS/LIST授权一次START，新段须产生可区分的记录变化。已知需要保全的记录继续按内容与指纹独立备份；最终下载复核允许固件自然覆盖导致旧基线消失，同时拒绝陌生新增、身份替换和计数回退。该兼容规则已有软件测试，真实多记录、覆盖与长时行为仍须设备验证。

保护停止：本次START所在连续连接已证实唯一新记录正在采集、uptime符合本次TIME窗口，仅日期锚不符合时，提供“停止并保留数据”。先持久保存保护请求，再发送一次STOP；原连接确认停止后换新连接独立保全，核对静止快照并归档异常尝试。开始成功、正式停止和真实边界仍为空，保全文件不生成实验上传包。STOP确认前断线、进程退出或记录身份变化时继续查询与保留证据，不凭残留数值ID补发控制命令；此类设备恢复仍待验证。

本功能覆盖独立入口、走路/跑步分段采集、整段参考步数与异常、本地保存/恢复、云盘和本机Python闭环、研究侧session结果及日汇总语义。具体活动的时间标注、在线步数预测与分类准确性评价属于后续算法工作；采集人数与周期属于实际研究安排。日统计遵守S11。

### 准备流程：以首次设置和管理面板替代旧T1b中转页

首次同页明确选择“研究编号”或“本地名称”，填写对应内容并选择佩戴位置；保存成功后按需授权并进入戒指搜索。选中戒指可靠保存后直接进入唯一采集首页，由采集服务连接、校时并核对记录。登记可离线完成，连接受阻时首页保留身份信息并提供恢复动作。

- 本地保存身份类型、稳定匿名编号、仅本机显示名称、installation UUID、已确认位置及所选戒指的地址/名称。研究编号采用3–24位ASCII字母或数字；本地名称最多40个字符，并始终生成与本次安装稳定关联的匿名ID。空闲时可更换当前身份，已有session不随当前设置变化。
- 准备信息写入成功后才进入下一步。写入失败保留上一份确认信息并允许重试；主文件损坏时优先恢复上一完整副本，失败则隔离损坏文件并开放重新登记，历史session和原始文件保持。
- 重开恢复准备信息；冷启动时，已有编号、位置和戒指且权限、蓝牙及必要定位条件齐备，自动尝试一次只读连接查询。条件不足时显示恢复动作，冷启动不自动弹出权限或设置界面；失败由用户重试。设备切换或断连后清除过期实时状态，不将上次连接记为当前连接。
- 选择戒指页只执行扫描和可靠保存，不持有采集连接。进入唯一首页后由独立前台服务接管BLE；正式owner执行STATUS/LIST、必要的电量与TIME、开始、停止、READ和session写入。固件INFO、常规电量与RSSI详情尚未接入正式入口，按原版差异门禁恢复；旧准备控制器属于不可达参考代码，不能作为已实现能力。
- 未连接、权限不足或STATUS未返回/超时时保留恢复入口。准备页查询只负责连接交接；采集服务以完整STATUS/LIST判断就绪。空闲既有记录保留为本次开始基线，不赋予当前被试编号，也不因数量或未知日期直接阻止新段；需要保全的指定记录才进入独立备份。采集中或归属不明的任务按恢复规则处理。
- HEALTH兼容15字节旧STATUS与16字节扩展STATUS；有符号错误码与无符号`error_reason`分别读取。旧包原因保持未提供，未知原因保留数值。E24仅对证据完整的历史充电错误开放一次开始尝试；成功确认仍要求错误码0，具体条件见下方。错误清除机制仍需设备证据确认。
- 首次设置页只保留身份和佩戴位置，选择戒指页只保留权限、搜索和候选设备。候选项沿用原版的设备名称与RSSI，地址尾号可作为辅助追溯信息；设备详情至少提供名称、RSSI、电量和固件，完整地址与Flash计数作为当前新增追溯信息。唯一首页承担连接状态、走路/跑步选择、每次清零提示及记录；旧注册、Oura、睡眠、Polar、评分和旧六类活动退出独立导航。

T1 的通过证据分别覆盖自动测试、APK 构建/身份检查和设备操作。真实戒指查询、应用强行停止后重开、升级与旧版共存未执行时保持待验证；准备流程通过不代表完整 session、上传或长时间采集已验收。

请求账本冻结session身份，分别保存开始/停止请求、确认、参考和本地文件；未知设备边界保持为空。账本v3增加开始基线与指纹，v4未确认请求归档，v5充电兼容，v6活动，v7未知日期保全证据，v8完成策略与放弃审计，v9保护停止审计，v10参考修订审计，v11 START命令入队证据，v12 STOP来源、观察时间及命令入队证据；兼容读取旧账本。研究manifest独立版本化：v2/v3保留历史自由活动，v4走跑分段，v5未知日期旧记录保全后的新开始证据，v6补齐手／手指、App版本和包创建时间，v7区分用户请求停止、设备自行停止及旧来源不明。旧缺失信息保持缺失，已冻结ZIP保持原文；演示与正式任务使用独立目录。

### 真实本地闭环的软件边界（T2b.2/T2c/T2d）

0.7.0-local已接入`RealCollectionService`、串行采集owner和原始下载适配器。START/STOP请求先持久化，命令入队、设备观察与账本确认分别处理。开始前取得同次连接的空闲STATUS与完整LIST；非空基线本身不阻止START，也不自动归入当前身份。开始许可绑定该完整基线，START后的新记录须可与之区分；STATUS/LIST矛盾、陌生新增或受保护记录被替换时停止推进。B19的新旧边界与覆盖机制继续实测。

开始确认要求同一连续连接中的唯一可区分新记录；账本保存基线、session ID、uptime/Unix指纹和计数。固件复用数值ID时，以记录指纹和两个时间锚判定新旧；设备时间未知时保留手机TIME证据与uptime，跨连接恢复继续要求完整指纹和单调计数。只有开始请求、没有已确认指纹时，重开保留待核对。已有停止请求仅查询确认，不自动重发STOP；观察到无请求的停止按异常收尾规则保全，不补造用户操作。

读数可靠保存后才启动READ。下载按冻结的session、戒指与记录指纹组织，断点保存连续偏移和前缀SHA；完成时核对总字节、packet记录数、无缝或一致重叠、完整解析、rfbin头及载荷重读CRC，最终文件以SHA-256入账。READ结束后再次取得完整STATUS/LIST并核对停止状态、记录身份和计数；目标尾部继续增长时从已持久前缀续传并重复最终复核，稳定后才标记本地完整。旧基线自然消失可接受，陌生新增、替换或计数回退保持恢复状态。完整文件和账本保存后，临时文件清理失败不会回退本地完成结果。协议没有DATA级session ID或设备CRC，连接代次隔离和完整记录查询由owner负责；手机CRC不能单独证明空中数据与设备Flash逐字节一致。

原始uptime保持原值，首末packet和LIST锚均不直接补造实际采集边界；当前样本覆盖记录为`not_assessed`。这些规则已有软件回归，实际记录身份、停止定稿、信号覆盖和后台行为继续按E18/B06–B09/B19验收。本地完整作为上传前置，0.7.1-upload的真实传输与研究侧处理见下节。

### 启动时序与就绪复查（E22）

本节保留E22时序依据；非零错误的当前例外与自动保全规则由下方E24补充。

开始前完成空闲STATUS/LIST及原文件保护检查，可靠保存请求后等待500ms，再发送一次START；从命令入队起等待1000ms，才发起首轮完整STATUS/LIST。若仍为空闲且完整状态及记录指纹与基线一致，间隔1500ms继续只读复查，含首轮最多3轮；期间保持开始等待，禁止重复开始。观察到与开始归属规则不符的记录变化、额外未知记录或采集中错误时保留待核对出口，结果不明时沿用原session恢复查询。

空闲连接查询出现非零错误时，先按E24检查是否满足充电兼容条件；其他情况以完整STATUS/LIST作有限复查，含初次最多3轮、相邻轮间隔1500ms。错误恢复为0、设备仍为空闲、状态和记录指纹保持一致时恢复开始入口；点击后仍须通过原始文件保全预检。持续未满足条件时显示“重新检查”；该动作重新连接查询。等待、断连、关闭与过期回调均受连接代次和任务门禁保护。

单独的-16不足以判断原因，必须结合扩展原因及新查询状态。旧版启动等待作为兼容性依据，Debug日志保留单调时钟的入队、发送、回调与状态观察，供时序复核。E21归档规则用于既有请求审计；新开始按E24判断，开始/停止成功继续要求error=0。历史设备结果见E22，当前结果见E24。

### 连续使用：充电错误兼容与旧记录自动保全（E24）

依据本轮用户确认，戒指存在旧记录不再要求被试清空设备或联系研究者。当前手机已有完整、匹配且通过校验的文件时直接复用；换手机、重装或更换戒指后出现的未归属闲置记录，由采集服务自动下载至独立`device-backups`目录，首页显示“正在保存已有数据”。原文件长度、SHA-256、容器头及载荷CRC验证完成、回执可靠落盘后，重新连接查询并开放开始。每条备份使用独立连接代次，每个READ窗口前核对同一完整STATUS/LIST，旧连接数据不能进入下一条记录。

备份只保存戒指地址、完整记录指纹、原始文件和保全回执，不赋予当前被试编号、参考步数或研究session，不自动上传。已知日期且指纹匹配时，重连复用已验证备份，中断后核对续传；未知日期按E26每个新连接重新完整保全。实际新START仍可能覆盖固件上一条记录，故完整原文件保全必须先于START；手机空间不足、原文件校验失败、正在采集或记录指纹不足时提供相应恢复路径，保留现有数据。

就绪与开始预检允许以下唯一非零错误组合：完整STATUS/LIST为空闲、`error_code=-16`且扩展`error_reason=1/charging`，随后在同一连接中重新查询BATTERY并报告未充电（0）。STATUS和BATTERY在检查时均须不超过5秒，发送START前再检查时效；等待期间矛盾状态、旧连接、缺少原因、仍充电或未知充电状态均不能授权开始。首页检查不替代点击开始后的独立新检查。请求及原始错误先持久化，500ms后最多发送一次START，再等待1000ms执行既有确认流程；重复点击、重开或重连不重发START。

成功开始、停止和完整设备记录仍要求错误码0及正确的新记录指纹。若实际采集中仍带异常，保留未确认请求，不能显示成功；本轮受控设备测试另有针对本次唯一新指纹的停止与隔离原文件保全出口，跨连接或进程退出后的此类异常恢复仍须继续验收。

本地账本升级v5，兼容v1–v4；开始基线保存可空`charging_recovery_evidence`，包含原始原因、BATTERY充电状态、两回复的接收时间与连接代次、检查时间。普通session继续产生原v2上传manifest；使用兼容路径的新session产生v3，并保留实际`-16`基线。Python逐项校验上述证据，v2不能隐式使用该例外，所有版本的成功确认证据继续要求错误码0。旧冻结ZIP、参考数据含义与分析资格保持原值。

### 未确认开始请求的受控归档（E21）

开始后始终未取得确认时，恢复页可提供“结束本次尝试”。用户填写简短原因后，采集服务重新建立连接并查询完整STATUS/LIST。归档仅适用于仍处于`start_requested`、没有开始/停止确认、参考、设备归属或本地数据的请求。新观察须证明戒指已停止，状态和完整记录清单与开始前基线一致；当前允许的错误码为0或已观察到的-16，比较时单独保留错误码原值。非空清单中每条记录须有非零设备UNIX锚，并精确对应本机已保存的真实文件，通过SHA-256、容器头及载荷CRC复核。

检查通过后原子保存归档时间、原因和设备观察，返回采集准备；固件仍报告错误时继续显示未就绪及重新检查入口。该操作仅查询与保存本地审计，START、STOP和DELETE命令次数均为0。设备正在采集、记录变化、身份或时间依据不足、文件损坏、断连、超时或保存失败时，保留原请求及保护状态。归档审计保留原session身份，不进入采集记录列表、上传或研究统计；下一次开始创建新session。该出口解决未确认请求的恢复，固件-16根因及后续真实开始仍须另行验证。

### 真实上传与活动专用导入（T2e/T3，证据E19/E20）

`FreeLivingSessionPackage`在首次发送前冻结manifest、原始rfbin、对应设备证据及ZIP哈希；重试校验同一包，上传次数和回执独立保存，不重写研究内容。真实目录的完整记录按持久上传选择排队，暂缓段仅接受主动上传；中断任务恢复，明确失败由用户重试。上传任务首次绑定的目标继续保留，更新本地配置不会迁移既有任务。真实回执核对后才显示上传完成；本地保全与云端接收分别表达。

每个新走路或跑步session只冻结一个ZIP并建立一个上传任务，名称分别为`ringfitness-session-walking-<session_id>.zip`和`ringfitness-session-running-<session_id>.zip`。队列和重试绑定确切文件名、长度与哈希，云盘回执同时匹配文件名和长度；一个任务失败不改变另一段。历史`ringfitness-session-<session_id>.zip`按原名和原字节继续重试。手机本地`package_version=2`描述新的冻结命名规则，ZIP内研究`manifest.version=7`继续描述数据字段契约，两者独立演进。文件名用于人工辨认，研究端活动类型仍以经校验的`manifest.activity_code`为准。

上传由独立JobService运行，采集页面与BLE任务保持原状态。0.7.2-recovery在正常准备页启动时恢复持久队列，无需先连接戒指或取得BLE权限；已排队、发送中断及已手动请求重试的任务重新等待网络，明确失败仍由用户在原记录中重试。系统强行停止后，下一次手动打开App触发恢复。首页显示全部本地完整但未上传的记录，以及最近三条已上传记录，按新到旧排列；失败重试留在对应卡片中，底部继续提供当前采集操作。旧上传完成不改变新session的编号、参考输入或采集状态。演示继续使用独立目录和模拟传输适配器。

原始文件缺失、内容变化或冻结包校验失败时，记录优先显示“戒指数据需要检查”，保留参考、文件和失败阶段。重试期间维持待检查状态，原始文件及冻结包重新校验通过后才清除。网络失败独立显示上传重试入口；任一坏任务只影响对应记录，其他完整记录继续上传。

已有上传尝试但目标任务文件缺失时，保持本地待检查状态，自动恢复与手动重试均不得按当前配置重建目标。仅从未尝试上传的pending记录可首次绑定；原目标无法确认时先恢复可信任务证据。

Python入口接收manifest v2–v7，保留原包、manifest及原始文件，生成每段唯一参考行、IMU/PPG CSV和质量报告；各版本的活动、恢复证据、停止来源和来源字段组合见第4节。同ID同ZIP重导幂等并复核既有产物；同ID异包及非法包分别保留冲突或拒收材料。`summary`当前是session索引，日汇总尚待实施。历史v1和睡眠包继续交原后端处理。运行方法见[活动导入器说明](../../backend/ringo_data/README.md)。

研究端自动读取按“同一云盘文件夹 → 本地接收目录 → Python导入与session索引”分层。`cloud-sync`从已登录Seafile客户端账号库只读取得唯一匹配账号的凭据，仅通过GET读取配置的资料库及目录直属ZIP。HTTPS同源、禁止重定向、凭据仅用于API；日志和下载回执不记录凭据及短期下载地址。读取配置、账号与映射保存在本机。

首次使用的接收目录须为空，并在联网前可靠保存来源标记；非空目录缺少标记或标记不匹配时保留原件并暂停。下载按配额和绝对期限逐块读取，完整长度与ZIP结构通过后，以内容SHA原子发布。只有已登记且长度、哈希复核一致的包进入导入；混入外包、未完成文件及已发布但未保存下载回执的包保持待核对，后者可经同一云端重新读回登记。重复扫描保持幂等，同名异内容分别保留，冲突与坏包有独立结果；输入和研究输出目录分离，操作系统文件锁防止并发覆盖并在进程终止后自动释放。E20已通过真实云端取回、重复运行与本机定时调用；未来新采集到达及跨整机重启触发继续验证。

样本绝对时间尚未校准，CSV的绝对时间列保持空值，原始uptime、相对偏移和设备锚推算值分列；时间缺口、重叠及回退保留。当前分析状态为`pending_review`，文件校验与上传成功均不自动赋予研究可用性。E19已验证人工网页原包读回，E20补时间偏差调查；时钟与采样边界依据核实后再评估覆盖资格。

## 3. 操作与状态

### 首次准备和身份

研究者指导完整操作，依据计步器说明统一佩戴。App 显示并记住编号与戒指佩戴位置，后续开始前可确认位置是否仍正确；位置变更影响以后新 session，采集中元数据快照保持不变，途中换位通过异常记录表达。

应用显示名为“步数采集”，applicationId为`com.nexthci.ringfitness.steps`；真实session和rfbin保存在独立应用私有目录，演示目录另行隔离。既有公共导出目录`Download/RingFitnessSteps/`保持独立命名；当前版本见本文开头。登记时显式区分研究编号与本地名称：研究编号采用3–24位ASCII字母或数字并规范化；本地名称最多40个字符，只用于手机显示，即使由纯字母或数字组成也生成匿名`participant_id`。兼容字段`participant_name`使用匿名编号，本地名称不进入session、ZIP、CSV或云盘路径。installation ID标记安装，session UUID在持久化开始请求时创建，再等待戒指确认采集。空闲时可切换身份，已有session保持创建时身份快照。

升级、重开或手机重启须保留已有身份与任务。当前数据位于应用私有目录，卸载或清除应用数据会删除未上传的session、参考和原始文件；正式交付前须提供并验证卸载前保全/导出路径，在保全完成前明确阻止把卸载重装当作故障恢复步骤。原版文件与历史交接资料保留。

### 每次采集

1. 被试站定、佩戴两种设备、清零计步器。App 展示简短提示；额外确认勾选是否必要留给可用性检查，清零由被试操作，App 无法自动读取计步器是否清零。
2. 点击开始，持久化唯一 session 及编号/位置快照，再发出命令。得到戒指开始证据后显示“采集中”；开始失败保留失败状态和日志，重复点击保持同一请求身份。
3. 被试进行所选走路或跑步活动，App展示真实采集和连接状态。换活动时先结束本段；一天可多次采集，无固定时长。
4. 被试站定点击结束。App 先确认戒指已停止，可靠保存结束边界及证据；未确认时显示停止处理中，重连后查询实际状态。
5. 停止确认后选择收尾方式。两种保存选择均输入整段总数并确认保存；数字立即持久化，再下载、校验对应Flash原始记录。后台上传遵从本段持久选择；放弃分支按本节新规则执行。
6. 简短异常入口暂定为“忘记清零／临时摘下戒指或计步器／计步器意外归零／其他异常”。选项可附简短说明和已知时间范围；时间不清楚时明确保存未知。无法提供数字的保存交互见 Q03。

主状态为“准备/选择活动 → 启动中 → 采集中 → 停止确认中 → 选择收尾 → 待填参考 → 参考已保存 → 下载/本地校验 → 手机保存完整”。选择上传时后台排队，选择稍后上传时持久等待手动操作；放弃由收尾进入二次确认及清理。缺失参考可在记录原因后继续保存；传输进度与研究质量分别表达。

异常保全路径：戒指断电或状态丢失而无法确认停止边界时，先保存当时可取得的计步器读数、观察时间与异常；有数字标为 unreliable，无数字保留 missing。界面继续显示停止/边界待核对，未知 ended_at_ms 为空。设备恢复后查询状态，确认可安全读取时继续下载；未落手机的原始记录保持待传保护。若边界最终无法恢复，由研究者决定分析资格。该路径保存的是不可靠参考证据，不能据此宣称正常采集已完成。

前一段戒指原始数据未安全落到手机前，保持待传保护，避免新任务覆盖 Flash。文件完整保存并校验后，云端重试应与下一段采集并行独立；用户无需等网络恢复才清零开始下一段。戒指能否同时容纳多个尚未下载的 session 暂不作为产品能力。

## 4. 数据契约与分析语义

原始文件保持`.rfbin` v2、参考字段保持`step_schema_version = 1`。历史manifest v2/v3使用`daily_activity_v2/free_living`，v4增加走跑任务声明，v5增加未知日期旧基线证据，v6补齐`ring_placement_schema`、`ring_hand`、`ring_finger`、`app_version`和`created_at`。新冻结包采用manifest v7，另存`stop_origin`和`stop_observed_at_ms`，使用户请求停止、设备自行停止和旧来源不明具有独立语义。Android与Python显式校验版本组合；下表区分任务声明、样本标签与后续质量扩展。

本地账本已落实参考值、来源、状态、参考保存时间、文件归属/校验及传输状态。v3增加`start_baseline`、`device_record_evidence`和`device_association_invalidated`；这些字段用于记录归属与恢复，不替代真实时间边界。导出的manifest保留研究快照，排除可变传输状态。未填写时`reference`为空；确认缺失时保存原因与`reference_saved_at_ms`，数字及`ground_truth_recorded_at_ms`保持null。演示文件与回执显式标记`simulated`，独立入口拒收。

| 字段或字段组 | 语义与校验 |
| --- | --- |
| `session_id`、被试编号、佩戴位置 | UUID 唯一；身份/位置为创建时快照；同日不同 session 分开保存 |
| `capture_purpose`、`activity_schema`、`activity_code` | purpose为`daily_activity`；历史`daily_activity_v2/free_living`保持原义，新段为`daily_activity_v3`配`walking/running` |
| `activity_selection_source` | 新走跑段为`participant`，表示被试声明的整段任务；历史自由活动不补造选择 |
| `activity_label_status`、`activity_label_source` | 均为`unlabelled`、`none`；逐样本真值标签为空，走跑选择不能提供时间边界或证明活动纯度 |
| `started_at_ms`、`ended_at_ms` | 版本化保存有明确来源的手机采集边界；设备精确边界存在时另列，不覆盖手机边界。无法确定的端点为空并标记 `capture_boundary_status = uncertain`，旧包空值保持原义 |
| 请求/确认、设备时间和覆盖信息 | 分别保存开始/停止请求、命令入队、确认时刻、戒指设备 session ID、uptime/Unix anchor、TIME侧证据、首末样本及时间来源/修正记录。手机时间表达命令／确认窗口，设备证据表达可达到的精确边界，两者不得混写 |
| `ground_truth_source` | `external_pedometer`，表示本实验指定参考来源 |
| `ground_truth_steps` | 确认的整数范围为 0 至有符号 64 位整数上限；缺失为 null。UI/后端拒绝负数、小数、布尔值、单位文本和溢出，不以工程上限宣称生理合理性 |
| `ground_truth_status` | `valid / missing / unreliable`。valid要求非负整数且无异常原因；missing要求null和原因；unreliable要求非负整数和原因。没有数字时统一使用missing。是否可用于分析另由完整性和边界共同决定 |
| `ground_truth_recorded_at_ms` | 确认数字的 UTC Unix 毫秒；有数字必有确认时间，无数字为空。异常说明保存时间另记 |
| `download_completed_at_ms` | 全部文件下载并校验后的处理时间，待完成时为空；与活动结束及填写时刻独立 |
| 文件清单 | 同一 session 下多个文件的名称、设备记录/片段 ID、字节数、SHA-256、已知时间范围/通道及对应派生文件，参考总数只置于 session 顶层 |
| `data_integrity_status`、质量与异常 | 本地使用 `pending / complete`，导出要求 `complete`，表示文件已完整保存和校验；样本覆盖与研究资格另记。当前导入产物保留原因、设备证据、时间告警及`quality.json`；结构化`anomalies[]`及发生时间范围仍待后续扩展 |

例：静坐记录确认0步，保存`steps=0, status=valid`；尚未填写时参考尚未确认；选择无法读数并保存原因后才记录`steps=null, status=missing`；忘记清零后填写562则保存`steps=562, status=unreliable`并记原因。缺失和异常记录保留为待核对参考。

时间校验需允许边界不明的异常档案被保存和导入。已知起止须有先后关系；单位、时区、手机改时/设备 uptime 重置等异常明确记录。发生不可解释的时间次序异常时保留为待核对数据，不靠改写原时间获得表面一致。时间对齐容忍度依据设备实测确定。

### 手机时间基准与协议补全（E25）

用户确认戒指日期时间未标定，时间基准采用手机。原版Android 0.5.3没有TIME SET/GET实现；当前校时能力来自参考Python SDK，并属于已确认的技术补齐，不能作为原版Android缺陷或既有能力表述。0.7.7-phone-time在新开始前先重新查询空闲STATUS/LIST并核对已有数据保护，再按参考SDK发送一次TIME SET（`23 00`＋UTC毫秒）。匹配当前连接的TIME STATUS须声明已同步，往返不超过3000ms，手机壁钟增量与单调计时差不超过250ms，设备Unix落在手机请求/回复窗口及该容差内。250ms是识别调时/异常回复的工程容差，测量精度和长时漂移另验。

只有TIME SET成功入队后才接收本轮TIME回复。确认后重新查询STATUS/LIST，旧记录指纹及计数须与校时前一致，再进入既有开始预检与等待。手机改时、超时、断线、记录变化或校时证据保存失败保留重试入口且不发START；实际发送START前再次检查手机时间连续性和30秒证据时效。页面使用既有开始等待状态，准备页、采集中重连和未完成session恢复均不自动写设备时钟。该范围与Python SDK在连接／重连路径校时的行为不同；采集中重连是否写时钟保持“证据不足”，先补只读TIME GET和长时连续性证据。校时请求/回复、双端时钟、连接代次与session绑定以独立原子JSON保存在手机，原有manifest及冻结ZIP继续保持原契约；校时审计上传和研究端直接消费该锚仍待下一契约切片，现有CSV不得宣称精确校准。

既有上传包可在独立研究输出目录重新导入，增加`phone_capture_window_v1`估算。以全部通道样本的最小/最大uptime与手机开始请求、停止确认构成可行平移区间，取其中点；各通道共用同一偏移，采样间隔、缺口和重叠保持原值。CSV另列`phone_estimated_unix_ms/iso`、`phone_earliest_unix_ms`、`phone_latest_unix_ms`及来源，quality保存方法、区间与假设。该区间以手机时钟稳定、设备标称计时速率及原session关联成立为条件，不包含未经测量的漂移或采样语义误差。原始`unix_ms=0`、确证时间空值和研究待核对状态均保留；填写与下载时间不参与对齐。

手机时序缺失/异常、uptime回退或环绕、信号跨度超过手机窗口、多文件缺少共同时间证据时，只保存未对齐原因。估算不赋予日汇总资格，也不按午夜拆分一个参考总数。既有导入回执保持幂等，重导新目录才能获得新增列。

协议补全当前严格检查INFO声明组件所需的`9 + 5 × count`字节，解析组件存在、型号及探测标志；未知值原样保留，0组件旧回复继续兼容。原版只需9字节基本头即可显示固件，因此严格解析保持“证据不足”，须用现有两枚戒指和两种手机验证，不得让可用的旧回复阻断准备。新版STATUS第16字节`error_reason`来自Python SDK，只用于诊断及严格的同连接charging恢复证据；15字节旧回复保持原因未知。原版空闲连接后约250ms查STATUS、约600ms查固件；当前正式owner在BLE ready后立即查询STATUS/LIST，准备页连续排入电量、INFO和STATUS。该节奏差异保持“证据不足”，须做单变量真机对照。STOP只发送一次并保存命令证据；当前工作区已恢复约500ms只查STATUS、仍采集时每约1000ms继续查询、首次stopped后等待约5000ms再取LIST，以及LIST迟到最多30轮的顺序。无STOP请求但归属证据完整的设备自行停止进入相同Flash定稿，再进入异常收尾；异常计数、身份变化、停止后又采集、错误及断线进入可恢复状态。连接恢复页以实际pending为当前任务，已保存上一段列入历史；无pending时可直接返回设备页，已保存段的上传失败在原记录内重试。上述时序的软件回归已通过，真实戒指行为仍待复测。

### 同段信号与一个总数

计步器清零后保持站定，戒指确认开始后活动；结束时站定，确认停止后等读数稳定再填数，减少两设备边界间额外活动。实际样本覆盖和计步器延迟计数仍需设备实测。异常时保留数据，不从读数猜测缺失时间的步数。

一段包含多个 IMU 文件时检查顺序、范围及重复，再合并对应信号的估计步数，与唯一参考总数比较。PPG 通道、重传文件及重复片段不增加参考数或 IMU 样本。历史 `.rfbin` 中的实际原始字节保留。

独立后端接收上述manifest v2–v7契约；旧`daily_activity_v1`包继续使用原交接后端，旧活动及未提供参考的含义保持原契约。未知schema/冲突组合进入拒收或冲突目录。合法缺失/不可靠参考档案可导入，分析资格单列为待核对；格式损坏或类型非法保留拒收依据。

自由活动每行可携带 session 场景元数据，真值活动标签保持空值；下游训练/评价显式排除未标注标签，避免将其转为 `other=0`。后续算法预测另记 `label_source=algorithm`、模型版本与推理范围，与人工/实验标签分列。

### 每日汇总

当前`summary`只输出逐session索引并标记重复原始内容或已知区间重叠；以下每日累计规则仍是待实现验收目标，0.7.1-upload不生成每日总数。

研究侧先依据边界、参考质量、样本覆盖和重复检查，生成 session 是否可分析及原因，保留规则版本。暂定仅明确通过检查的记录进入普通总步数评估；未决异常交由研究者复核，纳入阈值依据设备实测和研究分析要求确定。

每日按采集时记录的研究时区汇总：同日有效且区间互不重叠的记录去重后相加，同时报告覆盖区间和缺失/待核对记录数。发现不同 ID 的区间或原始片段重叠时隔离候选并报告冲突，待明确去重结果后累计。未开始、未佩戴和漏采的时间保留缺失。

例：上午 562 步、下午 438 步，结果为“当天已采集时段累计 1000 步”，同时展示两个覆盖时段。23:50–00:20 的一段共 300 步，只保留 session 总数，在涉及日期单列“跨日未分配”；不能凭时长分成 100 和 200，也不能两天各加 300。跨日记录仍可用于完整 session 评估。

“覆盖完整目标时段的全天步数”需先定义该日目标时段，并有完整覆盖证据；当前尚无正式目标时段和覆盖阈值，暂不出具此结论。参考计步器总数与未来算法预测日总数分别命名、分别保留来源。

## 5. 持久化、恢复与长时边界

| 情形 | 处理规则 |
| --- | --- |
| 开始始终未确认 | 保留原请求并重新查询；显式结束尝试时按E21重新连接、复核不变基线及已保全文件，可靠保存审计后释放该请求。异常或证据不足保持待处理；归档请求不计为有效采集，不产生上传包 |
| 采集中断连、进程退出或手机重启 | 恢复原session并查询戒指状态；按原版能力每约3秒持续重连，记录断线开始、恢复和无法连接区间。BLE缺连接和Flash缺信号分别记；找不到原始边界时标记uncertain，当前时刻仅记录恢复事件。当前实现仍为有限重连，属于应恢复项 |
| 停止待确认 | 保留停止请求及已知证据，重连查询；断电/状态丢失时按异常保全路径先保存可取得读数，未知边界保持空值，待设备可安全读取后下载；无法恢复边界交研究者核对，原 Flash 保持保护 |
| 待填参考退出 | 恢复任务与已持久化草稿；草稿与已确认数值区分，保留 Flash 待传保护 |
| 确认参考时写入失败 | 明确保存失败，允许重试；不推进下载、压缩或上传。停止信息与原文件保持可恢复 |
| 数字保存后重启 | 从持久记录恢复数字、来源、填写时间和异常，继续原下载任务，无需重新填写 |
| 停止确认后断连 | 收尾选择与参考填写继续可用，自动重连不抢占正在填写的输入框；数字可靠保存后等待戒指连接以下载。停止未确认时沿用异常参考规则 |
| 下载中离开采集页面 | 服务继续完成本段；本地完整且无新采集页面或待完成任务时释放连接所有权，准备页可修改佩戴或更换戒指，独立上传继续 |
| 下载中断 | 原设备记录、session与断点继续，完成后检查CRC/SHA、片段重叠和缺口；记录延迟出现时按原版每约2秒查询、最多30次，READ使用8 KiB窗口并有限自动补缺。当前16 KiB窗口和超时转手动恢复属于应恢复项；下载重启不得改写采集边界 |
| 上传失败/回执丢失 | 使用同一冻结ZIP、session、目标与哈希并保留原文件。“保存并上传”的普通网络/传输失败由持久任务最多自动尝试5次，达到上限或永久错误后提供手动重试；“稍后上传”继续等待用户首次手动触发。查看记录和手动上传不依赖BLE权限。回执丢失须先核对幂等结果，避免重复计入 |
| 数字/异常修订 | 最终确认前可修改；可靠保存后、首次上传尝试前仍可按交接说明修订。修订保留原值、时间和原因，可靠使旧ZIP失效并与上传队列串行；首次上传尝试后冻结，已发送记录不得静默覆盖。原版0.5.3没有计步器字段，依据来自步数采集交接说明 |
| 未配上传目标 | 保留本地；首次配置后，仅为未绑定且从未发送的记录绑定明确目标。已绑定/尝试上传的记录保持目标，更换位置需要另行迁移规则 |
| 文件相同或冲突 | 同 ID 同包幂等；同 ID 异包显式冲突；同批副本和不同 ID 重叠信号另做去重/异常检查。自动目录读取保留同步源文件，索引仅收录已校验的导入结果 |
| 低电、Flash 满、手机空间不足 | 能查询的量提前提示；失败时保留已知采集、参考与原始文件，标记截断/不确定并支持恢复；查询能力和提示阈值依据设备实测确定 |
| 长时后台运行 | 采集服务持续显示前台通知；首次使用处理通知权限并引导必要的电池优化豁免，上传在系统可能终止普通后台工作的时段使用可观察的前台保护。拒绝权限或系统限制时说明影响并保留任务 |
| 卸载或清除数据 | 私有目录会被删除。正式交付前提供卸载前保全/导出与校验路径；未保全记录明确阻止以卸载重装解决故障，升级安装继续保留数据 |

App 不预设固定采集时长。长时能力按短时、数小时、接近一天逐级探索，每一级记录戒指/手机电量、Flash 实际容量或可验证上限、存储增长、下载耗时/吞吐、手机峰值空间及解码资源。先确认不会覆盖唯一未保存的实验数据，再做容量边界试验。发布可用上限必须带硬件、固件、采样配置和测试条件；接近一天当前只是目标场景。

原版解码器在设备epoch异常或相邻时间跳变超过5分钟时，会依据手机开始时间和连续采样间隔重建确定时间。当前活动导入器保留原始uptime，逐项报告间隔、重叠和回退，绝对时间未知时保持空值，并另列手机估计区间；该改变已由“手机对齐且保留来源”的方向支持，仍须先补齐手机边界入包再验证。两条路径都不得改写原始字节，CSV样本完整性与设备时钟准确性分别验收。
