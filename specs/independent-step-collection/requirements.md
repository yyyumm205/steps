## 1. 本功能边界与当前事实

统一流程是“开始采集 → 正常生活 → 结束采集 → 填写本次计步器总步数 → 保存并上传”。例如 P001 从 09:00 采到 11:00，期间走路、坐着工作、短暂跑步，最后填写 562；全部对应信号和一个参考值 562 属于同一 session。当天 15:00 再次采集时先清零计步器，创建另一个 session。

本功能覆盖独立入口、自由活动采集、整段参考步数与异常、本地保存/恢复、云盘和本机 Python 闭环、研究侧 session 结果及日汇总语义。具体活动的时间标注、在线步数预测、分类准确性评价、正式人数与周期留在后续。首页日汇总卡片和图表暂不列为最近的 T1 切片交付；任何显示的日统计都遵守 S11。

### T1 已交付的独立准备边界

T1 交付可打开、可离线登记、可保存准备信息并查询戒指状态的开发版。首次同页填写研究者分配的编号与佩戴位置，点击“保存并连接戒指”；保存成功后检查权限和系统条件，条件满足便直接搜索。选中戒指可靠保存后回首页连接，查询结果自动显示。登记可在离线或蓝牙不可用时完成，连接受阻时保留信息并提供恢复动作。“开始采集”保持禁用并标明待开放，完整采集在 T2 接通。

- 本地保存规范编号、稳定的 installation UUID、已确认位置及所选戒指的地址/名称。编号一经登记，本切片保持固定；Q01 确认后再开放更换。重复登记相同规范编号不创建新身份。
- 准备信息写入成功后才显示保存成功。写入失败保留上一份确认信息并允许重试；已有文件损坏时保留原文件、提示研究者处理，阻止重新登记覆盖。
- 重开恢复准备信息；冷启动时，已有编号、位置和戒指且权限、蓝牙及必要定位条件齐备，自动尝试一次只读连接查询。条件不足时显示恢复动作，冷启动不自动弹出权限或设置界面；失败由用户重试。设备切换或断连后清除过期实时状态，不将上次连接记为当前连接。
- 设备准备只执行扫描、连接、电量、INFO 固件和 HEALTH STATUS 查询。独立控制器不绑定旧采集服务，不发出开始、停止或数据读取命令，也不创建 session、下载或上传。
- 未连接、权限不足、STATUS 未返回/超时、设备正在采集、状态错误或报告有记录时，准备结果保持未就绪或待核对。STATUS 的字节数/记录数只能表明戒指报告有数据，无法判断其是否已下载；不自动接管这些记录或赋予当前编号。
- 准备页保留必要字段、当前步骤、状态与恢复动作。自由活动、每次清零、站定及稳定读数提示在 T2 对应操作时呈现；旧注册、Oura、睡眠、Polar、评分和活动选择退出独立导航。

T1 的通过证据分别覆盖自动测试、APK 构建/身份检查和设备操作。真实戒指查询、应用强行停止后重开、升级与旧版共存未执行时保持待验证；准备流程通过不代表完整 session、上传或长时间采集已验收。

T2a初始切片交付请求账本：冻结session身份并保存开始/停止请求及确认，缺少设备证据时边界保持未知；该切片的31项JVM与后续API31默认存储检查已有通过证据。T2-P在同一账本中增加参考保存、文件校验、归档和传输状态，并由演示页面调用；真实采集与原始文件传输仍待完成。

页面只提交意图和显示状态。T2服务接入时由单一前台采集服务持有连接、协调器与任务；页面返回或进入后台不会主动断开采集连接。当前T1的Activity退出断连规则只适用于准备功能，服务接入与生命周期验收完成前保持真实开始入口关闭。

### T2b.1 的软件边界

T2b.1初始切片新增纯Kotlin协调器及测试，复用T2a请求账本，协议保持原样；T2-P已将其接入演示，正式蓝牙适配器和服务仍待接入。先保存请求再发命令，重复调用不重发START；命令入队、设备状态观察与账本确认分别处理。开始前按当前连接取得空闲STATUS与完整LIST；仅接受无旧记录的保守基线，指定旧记录的例外仍按B19受控验证。已完整保存的本地记录可归档，待传保护继续覆盖尚未安全保存的原始数据。

开始关联要求同一连续连接、发送后状态及完整记录列表中的可区分新记录。该软件判据没有协议nonce/boot ID保障，其可用性与固件语义需实测；不以STATUS或LIST锚直接生成真实起止时间。断连、进程恢复、设备ID复用或证据不足时只查询并保持待核对，不自动接管或重发。确认保存失败不发布采集中/待填参考，不解除待传保护。参考保全软件路径已由T2-P验证；真实服务恢复、参考与设备时段对应以及Flash下载由后续切片完成，T2b.1通过仅证明替身条件下的协调规则。

### T2-P：完整路径的开发演示（已实现，证据E15）

0.6.5-t2p在准备页顶部提供“体验完整流程”，无需实体戒指或网络即可进入。入口仅包含在Debug构建中，演示Activity不导出；使用本节既定顺序，覆盖独立体验登记、日常打开、开始/停止等待、参考填写与保存、模拟传输及失败恢复。研究流程与数据含义仍以总纲为准。

- `StepCollectionActivity`通过结构化状态呈现原生页面；演示复用`FreeLivingCaptureCoordinator`和`FreeLivingSessionStore`，设备及传输结果集中在Debug适配层。应用进程中的单一串行owner持有任务，页面订阅/退出不取消任务。全程显示“设备与传输为模拟”；真实服务的生命周期能力仍由T2b.2验证。
- 示例编号、戒指、session、合成文件、参考数字和任务保存在应用私有`files/collection-demo/`。本地保存、读回、文件归属和SHA-256校验实际执行；正式目录保持原样，演示不发送真实BLE命令或云盘请求。发布构建不含演示入口，正式连接失败保持真实失败状态。
- 开始/停止按模拟设备证据确认；参考有效0、尚未确认、missing与unreliable分别表达。有数字记录确认时间，无数字时`ground_truth_recorded_at_ms`保持null，原因保存时间另记。原子保存失败留在输入页，可靠保存后才进入文件阶段；停止不明时可先保存不可靠读数或缺失原因，真实`started_at_ms`/`ended_at_ms`仍为null。
- 合成文件完整保存前保持当前任务保护；保存校验后，旧段待重试上传与下一段采集可独立进行。进程重开恢复当前任务及归档中的待处理传输，FAILED任务由用户重试；重复保存、下载和回执处理保持同一session。演示设备的持久UUID证据仅支持测试恢复，真实戒指的归属和边界仍须另取证。
- “演示选项”提供开始/停止确认超时、原子保存失败、下载失败、上传失败及断连。B23/E15记录23项运行层JVM、23项新增账本JVM及8项原生页面测试，并保留已有测试的适用范围；完整版本合计193项JVM、25项Android及Debug/测试APK/Release构建通过。
- Q01/Q02继续待确认；演示未开放更换正式编号或已确认读数修订。真实T2b.2/T2c/T2d、云盘读回、后端和长时能力按B06–B16继续接通并取证，合成文件与回执只用于软件验证。

## 3. 操作与状态

### 首次准备和身份

研究者指导完整操作，依据计步器说明统一佩戴。App 显示并记住编号与戒指佩戴位置，后续开始前可确认位置是否仍正确；位置变更影响以后新 session，采集中元数据快照保持不变，途中换位通过异常记录表达。

T1 采用显示名“步数采集”、applicationId `com.nexthci.ringfitness.steps` 和公共目录 `Download/RingFitnessSteps/`，应用私有目录由独立安装身份隔离；当前开发版本为 `0.6.5-t2p`。编号采用 3–24 位 ASCII 英文字母或数字，去首尾空格，统一小写；后续 session 的 `participant_id`、`participant_name` 均使用该规范编号。installation ID 标记安装，session UUID 在持久化开始请求时创建，再等待戒指确认实际采集。研究者维护发放表，离线登记只做格式校验。编号更换见 Q01，T1 暂不提供切换入口。

升级、重开或手机重启保留已有身份与任务；卸载或清除应用数据后的自动任务恢复不在本次范围。原版文件与历史交接资料保留。

### 每次采集

1. 被试站定、佩戴两种设备、清零计步器。App 展示简短提示；额外确认勾选是否必要留给可用性检查，清零由被试操作，App 无法自动读取计步器是否清零。
2. 点击开始，持久化唯一 session 及编号/位置快照，再发出命令。得到戒指开始证据后显示“采集中”；开始失败保留失败状态和日志，重复点击保持同一请求身份。
3. 被试正常生活；活动变化无需操作，App 展示采集和连接的真实状态。一天可多次采集，无固定钟点、固定时长或整日限定。
4. 被试站定点击结束。App 先确认戒指已停止，可靠保存结束边界及证据；未确认时显示停止处理中，重连后查询实际状态。
5. 被试等读数稳定，输入整段总数。暂定按钮“保存并上传”；确认数字后立即持久化，再启动 Flash 下载、打包和上传。正常路径只输入一个总数，途中步数合并计算。
6. 简短异常入口暂定为“忘记清零／临时摘下戒指或计步器／计步器意外归零／其他异常”。选项可附简短说明和已知时间范围；时间不清楚时明确保存未知。无法提供数字的保存交互见 Q03。

主状态为“准备 → 启动中 → 采集中 → 停止确认中 → 待填参考 → 参考已保存 → 下载/本地校验 → 排队上传 → 上传完成”。缺失参考可在明确记录原因后进入异常保存分支；传输进度与数据质量分别展示，例如“已上传，参考值待核对”。

异常保全路径：戒指断电或状态丢失而无法确认停止边界时，先保存当时可取得的计步器读数、观察时间与异常；有数字标为 unreliable，无数字保留 missing。界面继续显示停止/边界待核对，未知 ended_at_ms 为空。设备恢复后查询状态，确认可安全读取时继续下载；未落手机的原始记录保持待传保护。若边界最终无法恢复，由研究者决定分析资格。该路径保存的是不可靠参考证据，不能据此宣称正常采集已完成。

前一段戒指原始数据未安全落到手机前，保持待传保护，避免新任务覆盖 Flash。文件完整保存并校验后，云端重试应与下一段采集并行独立；用户无需等网络恢复才清零开始下一段。戒指能否同时容纳多个尚未下载的 session 暂不作为产品能力。

## 4. 数据契约与分析语义

下表为暂定字段方案，行为含义遵循总纲。原始 `.rfbin` 保持 v2；容器 `manifest.version = 2`，增加 `step_schema_version = 1` 区分新参考步数契约。新活动 schema 暂定 `daily_activity_v2`。三个版本分别表达容器、步数契约和活动元数据，由双端显式校验；不能仅加枚举而继续旧标签逻辑。

T2-P已在本地账本落实参考值、来源、状态、参考保存时间、文件归属/校验及传输回执。该账本采用独立的版本化存储格式；新ZIP清单生成与后端契约仍需后续实现。未填写时`reference`为空；确认缺失时保存原因与`reference_saved_at_ms`，数字及`ground_truth_recorded_at_ms`保持null。演示文件与回执显式标记`simulated`，不进入实验上传链路。

| 字段或字段组 | 语义与校验 |
| --- | --- |
| `session_id`、被试编号、佩戴位置 | UUID 唯一；身份/位置为创建时快照；同日不同 session 分开保存 |
| `capture_purpose`、`activity_schema`、`activity_code` | 分别为 `daily_activity`、`daily_activity_v2`、`free_living`；表示采集情境 |
| `activity_label_status`、`activity_label_source` | 自由活动固定为 `unlabelled`、`none`；逐样本真值标签为空。与旧 `other` 已知类别分开 |
| `started_at_ms`、`ended_at_ms` | 经证据支持的采集边界，UTC Unix 毫秒；无法确定的端点为空并标记 `capture_boundary_status = uncertain`。已确认端点保持不变 |
| 请求/确认、设备时间和覆盖信息 | 分别保存开始/停止请求与确认时刻、戒指设备 session ID、uptime/Unix anchor、首末样本及时间来源/修正记录。`capture_boundary_status` 暂定 `confirmed / uncertain`，另记时区与偏移。手机回调时间只证明收到确认 |
| `ground_truth_source` | `external_pedometer`，表示本实验指定参考来源 |
| `ground_truth_steps` | 确认的整数范围为 0 至有符号 64 位整数上限；缺失为 null。UI/后端拒绝负数、小数、布尔值、单位文本和溢出，不以工程上限宣称生理合理性 |
| `ground_truth_status` | `valid / missing / unreliable`。valid 要求确认整数，missing 要求 null；unreliable 可保留实际填写的非负整数或 null，并附异常原因。是否可用于分析另由完整性和边界共同决定 |
| `ground_truth_recorded_at_ms` | 确认数字的 UTC Unix 毫秒；有数字必有确认时间，无数字为空。异常说明保存时间另记 |
| `download_completed_at_ms` | 全部文件下载并校验后的处理时间，待完成时为空；与活动结束及填写时刻独立 |
| 文件清单 | 同一 session 下多个文件的名称、设备记录/片段 ID、字节数、SHA-256、已知时间范围/通道及对应派生文件，参考总数只置于 session 顶层 |
| `data_integrity_status`、`anomalies[]` | 完整性暂定 `pending / complete / incomplete / uncertain`；异常含类型、报告时间、已知发生范围或未知标记。完整性结论保留原始证据及处理版本 |

例：静坐记录确认 0 步，保存 `steps=0, status=valid`；尚未填写为 `steps=null, status=missing`；忘记清零后填写 562，保存 `steps=562, status=unreliable` 并记原因。三者均保留，后两者不自动进入正常参考评估。

时间校验需允许边界不明的异常档案被保存和导入。已知起止须有先后关系；单位、时区、手机改时/设备 uptime 重置等异常明确记录。发生不可解释的时间次序异常时保留为待核对数据，不靠改写原时间获得表面一致。时间对齐容忍度依据设备试运行决定。

### 同段信号与一个总数

计步器清零后保持站定，戒指确认开始后活动；结束时站定，确认停止后等读数稳定再填数，减少两设备边界间额外活动。实际样本覆盖和计步器延迟计数仍需设备实测。异常时保留数据，不从读数猜测缺失时间的步数。

一段包含多个 IMU 文件时检查顺序、范围及重复，再合并对应信号的估计步数，与唯一参考总数比较。PPG 通道、重传文件及重复片段不增加参考数或 IMU 样本。历史 `.rfbin` 中的实际原始字节保留。

后端为新契约开显式分支：旧 `daily_activity_v1` 包保留原有活动含义，缺少参考字段保持未提供；未知 schema/冲突组合进入拒绝或隔离记录。合法缺失/不可靠参考档案可导入，另标分析资格；格式损坏或类型非法不作为合法实验数据。

自由活动每行可携带 session 场景元数据，真值活动标签保持空值；下游训练/评价显式排除未标注标签，避免将其转为 `other=0`。后续算法预测另记 `label_source=algorithm`、模型版本与推理范围，与人工/实验标签分列。

### 每日汇总

研究侧先依据边界、参考质量、样本覆盖和重复检查，生成 session 是否可分析及原因，保留规则版本。暂定仅明确通过检查的记录进入普通总步数评估；未决异常交由研究者复核，纳入阈值在试运行后确定。

每日按采集时记录的研究时区汇总：同日有效且区间互不重叠的记录去重后相加，同时报告覆盖区间和缺失/待核对记录数。发现不同 ID 的区间或原始片段重叠时隔离候选并报告冲突，待明确去重结果后累计。未开始、未佩戴和漏采的时间保留缺失。

例：上午 562 步、下午 438 步，结果为“当天已采集时段累计 1000 步”，同时展示两个覆盖时段。23:50–00:20 的一段共 300 步，只保留 session 总数，在涉及日期单列“跨日未分配”；不能凭时长分成 100 和 200，也不能两天各加 300。跨日记录仍可用于完整 session 评估。

“覆盖完整目标时段的全天步数”需先定义该日目标时段，并有完整覆盖证据；当前尚无正式目标时段和覆盖阈值，暂不出具此结论。参考计步器总数与未来算法预测日总数分别命名、分别保留来源。

## 5. 持久化、恢复与长时边界

| 情形 | 处理规则 |
| --- | --- |
| 采集中断连、进程退出或手机重启 | 恢复原 session，查询戒指状态；BLE 缺连接和 Flash 缺信号分别记。找不到原始边界时标记 uncertain，当前时刻仅记录恢复事件 |
| 停止待确认 | 保留停止请求及已知证据，重连查询；断电/状态丢失时按异常保全路径先保存可取得读数，未知边界保持空值，待设备可安全读取后下载；无法恢复边界交研究者核对，原 Flash 保持保护 |
| 待填参考退出 | 恢复任务与已持久化草稿；草稿与已确认数值区分，保留 Flash 待传保护 |
| 确认参考时写入失败 | 明确保存失败，允许重试；不推进下载、压缩或上传。停止信息与原文件保持可恢复 |
| 数字保存后重启 | 从持久记录恢复数字、来源、填写时间和异常，继续原下载任务，无需重新填写 |
| 下载中断 | 原设备记录、session 与断点继续，完成后检查 CRC/SHA、片段重叠和缺口；下载重启不得改写采集边界 |
| 上传失败/回执丢失 | 使用同一冻结 ZIP、session 与哈希，保留原文件；排队自动恢复与失败后手动重试分别可检查。强行停止期间等待手动打开后恢复 |
| 数字/异常修订 | 最终确认前可修改；本地草稿变化使旧 ZIP 失效。参考快照的锁定按 Q02；下载时间、文件清单等处理字段随后补齐，首次发送前冻结整个 ZIP。已发送后保留原记录；后续纠错是否提供研究者补充记录见 Q02 |
| 未配上传目标 | 保留本地；首次配置后，仅为未绑定且从未发送的记录绑定明确目标。已绑定/尝试上传的记录保持目标，更换位置需要另行迁移规则 |
| 文件相同或冲突 | 同 ID 同包幂等；同 ID 异包显式冲突；同批副本和不同 ID 重叠信号另做去重/异常检查 |
| 低电、Flash 满、手机空间不足 | 能查询的量提前提示；失败时保留已知采集、参考与原始文件，标记截断/不确定并支持恢复；查询能力和提示阈值依据设备实测确定 |

App 不预设固定采集时长。长时能力按短时、数小时、接近一天逐级探索，每一级记录戒指/手机电量、Flash 实际容量或可验证上限、存储增长、下载耗时/吞吐、手机峰值空间及解码资源。先确认不会覆盖唯一未保存的实验数据，再做容量边界试验。发布可用上限必须带硬件、固件、采样配置和测试条件；接近一天当前只是目标场景。

现有解码/下载存在时间归一化逻辑，可能把超过 5 分钟的间隔重建为连续时间。完整性检查必须追溯原始包、uptime 与锚点，并记录修正；CSV 连续本身不足以证明无缺失。

## 6. 已确认、暂定与待确认

**已确认：** 自由活动、自主起止、一日可多段；每次清零；同段一个总数且允许 0；结束确认后填写并立即可靠保存；编号/位置记忆；独立计步器唯一设备参考；退出 Oura/睡眠；自己的云盘及本机后端；异常保留、恢复与长时实测。原 Q02“清零还是差值”已由用户本轮需求解决。

**本轮采用的工程方案：** 应用名/ID、编号规范与独立准备存储按T1落实；T2-P已落实本地参考、文件和任务状态及其原生演示路径，实际通过项见E15。ZIP/后端schema、异常时间范围、真实服务恢复及研究侧日汇总继续按后续切片实现和验收；编号更换与确认后的参考纠错保留Q01/Q02状态。
