## 3. 长时与时间完整性测试协议（B16）

试验梯度暂定“约10分钟 → 约1小时 → 数小时 → 依据实测探索接近一天”；它是测试安排，软件不以此固定 session 长度。前一级未完成数据保全、解码和质量核查时，先解决其失败或记录限制再延长。

每级提交如下记录，缺项填写“未测/查询不支持”：

| 测量组 | 记录和检查方法 | 判定 |
| --- | --- | --- |
| 版本与开始条件 | 手机/系统、App/APK、戒指/固件、计步器型号/佩戴方式、HEALTH采样模式、开始电量与可用空间 | 可复现；模式相同的工况才可比较 |
| 续航 | 戒指和手机起末电量，采集中可查询时记录中间值，记录实际停止/掉电时刻 | 完成目标级次且无未标记截断才记该级成功；仅有耗电率不外推整天通过 |
| Flash与手机空间 | 查询实际容量/剩余量；不支持则记录写入记录数、字节增长和已验证下限；记录手机 raw+临时下载+ZIP 峰值占用 | 满后的覆盖/停止/报错行为明确；无法测得上限时保留未知，不用文件大小声称容量充足 |
| 时间与连续性 | 保存原始包及uptime/Unix anchor、开始/停止请求和确认、首末样本、填写/下载完成；比较手机/设备时钟，报告修正前后间隔及修正数量 | 下载延迟不改活动边界；真实缺口和设备重置可见。原代码5分钟修正规则不得掩盖缺失；没有证据的边界保留不确定 |
| 多文件与数据完整性 | 清单计数/哈希/CRC、各片段时间/通道、缺失和重复样本、总有效覆盖 | 文件切分后仍对应一个session和一个参考；无未解释的丢失/重复或时间倒退才记正常完整。对齐容忍度/丢样阈值待试运行确定 |
| 下载/网络/解码 | 实测下载秒数与吞吐、重连续传额外耗时、上传/解码耗时及内存/磁盘；与上传读取超时、后端文件/解压限制对照 | 在实际程序边界内完成；失败保持恢复材料，不将超时算入活动；只模拟大文件通过不能替代长时硬件证据 |
| 故障边界 | 专用测试session模拟手机空间不足/进程或设备重启；在数据已保全的设备上测低电/Flash容量边界，无法安全重复则报告限制；复核 B08 的停止边界丢失路径 | 未下载原始记录受保护；参考/已知边界持久，截断明确；读数先保全，可安全读取后续传，永久不明边界交研究者判断。未触发的故障保持待验证 |

报告分别给出“软件检查通过”“该硬件/固件下实测成功时长”“失败/未测工况”。某级失败不能用较短成功记录替代；接近一天未执行时继续标为待验证。正式实验时长上限和质量阈值基于上述证据审阅确定，不能在此写成已支持24小时。
