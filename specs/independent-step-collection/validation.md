# 独立计步实验 App：验收草稿

依据：[总纲](../../CONSTITUTION.md) 1.1.0、[需求](requirements.md)、[计划](plan.md)。状态：待审阅。以下均是预期检查，新 App 尚未实现或执行这些检查。

## 1. 已有证据与阶段边界

历史原版：[E01/E02](../phase-0-baseline/validation.md) 的 25 项 JVM 单测通过报告、0.5.3 debug APK；原版恢复、真机采集和本机 Python 尚无执行证据。它们不能证明新 App 的编号、安装隔离或步数功能通过。

用户已确认设备可用、自己的云盘及本机后端。旧用户服务配置从依赖中撤销。当前源码仍含旧注册登录和默认上传地址，三个 ground_truth 字段仍待开发。重新规划并未把阶段 0 或后续真机项目标为完成。

## 3. 通过条件与未决事项

- T1 通过 B02、B03、B04a、B05 只表示独立入口可用。跨安装归档、步数记录与上传数据闭环由 B04b、B06–B11 验收。
- 构建、自动测试、真机验证分别提供证据，未执行/受条件限制的项目单独保留。旧版全流程未执行，不因撤销账号依赖标为通过。
- 待确认 Q01（编号更换）、Q02（计步器操作）、Q03（最终确认与纠错）在实施对应行为前定稿；其余已明确方向可先准备。
- 信号和参考步数按同一 session 的有效时间范围关联。停止未确认、设备时间失真或边界缺失时记录为异常，交给研究者核对；这种样本不能算正常采集验收成功。
- 原始 `.rfbin` 字节与格式保持，字段新增在元数据层；云盘和本机测试目录与原平台数据分开。较大规模的 5 次走路、5 次跑步及数据质量阈值按总纲后续阶段执行。
