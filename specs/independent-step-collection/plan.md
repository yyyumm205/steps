# 独立计步实验 App：自由活动执行计划

依据：[总纲](../../CONSTITUTION.md)、[需求](requirements.md)和[验收标准](validation.md)。沿用`codex/free-living-session-spec`。当前交付延续2.1.0的自由活动运行基线；3.0.0走跑分段修改按用户要求暂停，保留待续。准备、演示及真实读入链路已有E11–E20证据，E21–E24补充设备诊断、请求恢复、旧记录保全和有限充电兼容。本轮补齐手机时间与SDK兼容（E25），最终以测试者独立完成真实流程作为试用门禁。

## 1. 当前状态与范围

**当前优先切片：手机时间与SDK兼容补全（0.7.7-phone-time，E25）。** 走路/跑步分段开发按用户要求暂停，已有未提交改动保留并与本切片隔离。完成新采集前手机校时与本地审计、INFO组件完整解析、STOP有限只读确认和已完成记录的恢复页呈现；研究端为旧包另生成可追溯的手机时间估算。自动检查、构建、模拟器页面与真实TIME协议逐项记录E25，原APK及历史证据保持原适用范围。

SDK对照结论：继续复用现有串行命令队列、设备身份绑定、Flash断点、重复片段比对及完整长度/CRC/SHA校验。SDK的超时返回部分下载、按相近名称重连及每次重连自动校时不迁入正式路径。后续按依赖推进：①校时审计进入版本化上传证据，结束及重连时只读TIME GET，验证手机锚到样本的映射、重启及长时漂移；②保存完整INFO观察，并接入正常采集期间的电量刷新，避开控制预检及充电兼容窗口；③未知设备Unix记录的跨连接保全与连续开始回归；④真实短采及断连/下载/进程恢复，随后长时与独立操作验收。电量刷新不自行设低电硬门槛；温度、录音、HID与OTA不属于当前步数闭环。原远程“保存后自动卡住”的完整触发链仍需现场日志复核，时间估算与该故障分别验收。

上一切片0.7.6-charging-recovery（40，E24）已从App端兼容历史充电错误，并以自动备份取代“有未归属旧记录就阻塞”的流程。复用真实采集owner、原始下载和现有页面；后台保全、就绪、一次开始、停止与本地保存共同验收。E23的357项JVM和只读设备证据保留原版本范围。

E24实现与检查已完成：Python 179项、Android 394项JVM、45项模拟器、相关构建及独立审查通过；三星原位安装、自动备份、隔离短采、重开复用通过。旧记录备份断点、不同记录隔离和充电兼容由软件测试覆盖，实机故障注入另验。设备错误码在旧APK上已重新观察为0，故实机正常短采与`-16/charging`兼容分支分别记录，后者仍待真实复现。

下一项路径：站定清零并佩戴计步器 → 正式页面完成一次短采及读数保存 → 手机上传 → 研究端自动发现唯一新session。开始前核对手机设置、设备时间证据和旧文件备份；结束后核对原始文件、参考数、边界及云端/研究端哈希。需要用户配合的动作集中在清零、活动和读数。随后补采集/下载中断与进程恢复、逐级长时；未确认开始后出现带错误的采集中状态，尤其跨连接恢复，继续作为开放独立试用前的恢复验收项。

Q01/Q02继续不阻塞上述正常路径；计步器型号/佩戴方式和时间/覆盖容忍度在对应设备验收前补齐。原始证据留本地，正式记录只保留脱敏结果。

## 4. 采集接入的复用边界与迁移顺序

旧 RingCaptureService 同时管理采集、身份和上传，不能把准备 Activity 直接绑定过去。源码核对发现：旧路径在发送START后建立身份、收到任意collecting状态自动接管、用下载完成时刻补结束时间。这些行为与新session契约冲突。

0.7.0-local落实既定迁移：独立协调器管理持久请求和设备对应，前台服务独占采集RingBleClient；Activity只发用户意图和显示状态。准备控制器在交接前释放连接，原版服务与接口保留；原始文件继续使用rfbin v2。后续若改变实验流程或数据语义，先确认需求。

具体边界：

- START/STOP返回成功只代表命令入队；状态展示依赖对应设备证据和账本成功写入。一次STATUS不能单独证明新记录归属。
- 对START结果不明的恢复先查询；设备重启、未知归属或边界丢失保持异常，不以手机当前时间补造真实边界。
- LIST按已确认的记录身份匹配，不能自动选“最新记录”归入当前被试。
- 停止确认、参考确认、下载完成分别持久；文件清单和后续边界证据可补齐，参考确认锁定不阻止处理字段更新。
- 独立下载适配器保留原始片段，只有最终文件及账本可靠保存后才清理临时文件；旧HealthFlashDownload保持历史行为。独立上传使用RealUploadQueue和冻结包，不接入旧UploadSessionStore的回退路径。
- 旧实时IMU/PPG同步文件写入受主线程回调调整影响；若启用实时流，先将I/O移到有序后台并验关闭/落盘，准备查询通过不代表采集性能通过。
- 新旧包采用明确版本分路。独立入口已同步容器v2/rfbin v2、step_schema_version=1与daily_activity_v2；旧v1继续使用原交接后端，当前新入口不代替旧契约处理。

## 5. 实物前置条件与验收门禁

指定约5MB旧记录已获准无需保留。E18已核对精确设备基线，并实测START覆盖该旧记录、复用数值ID和更新双时间锚；无需新增恢复/迁移任务。此结论仅适用于已测设备与固件。后续START仍须检查空闲状态、记录指纹及原始文件已完整落盘；其他未识别或未保存记录继续受保护。

本地真实采集验证需要：手机解锁并允许系统权限、指定戒指有电、计步器可用并按统一方式佩戴；型号与佩戴说明补录到受控设备记录。T2e/T3上传读回另需云盘读取配置，手机上传目标与Python读取位置必须一致。真实链接、账号、凭据和绝对本机路径留在本地配置。

长时验证按短时、约1小时、数小时逐级推进，再依据证据探索接近一天；这些是测试梯度，不是软件限制。每一级核对电量、存储增长/满后行为、样本覆盖、手机下载与峰值空间、上传/解码耗时和恢复。软件超时、时间窗口和解压限额不能当作设备支持时长。跨午夜只有一个参考总数时保持整段，不拆分两日真值。

进入小规模试用前须同时满足：

- 一名按指导准备的测试者独立完成真实采集，混合活动只填写一个同时间段总数。
- 有效零步、缺失、不可靠记录可分辨，保存/重启后保持一致。
- 手机、manifest、云盘文件和后端记录逐字段对应，原始文件/派生CSV可追溯。
- 重启、断连、下载中断、上传失败/回执丢失的关键恢复路径通过，重复导入不重复计数。
- 已验证时长、设备/固件与未覆盖条件明确；再确定人数、周期和质量阈值。
