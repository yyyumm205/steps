## 3. T1b 已完成行为与验收

本轮修改范围是准备 Activity、PreparationStore 的兼容登记接口、导航/存储测试及版本和规格。T2a账本、底层协议、BLE队列与旧传输组件继续复用，未在此轮接入采集。

1. **合并首次信息并继续连接。** 编号与六种位置同页，“保存并连接戒指”一次原子保存后检查权限及蓝牙条件，条件满足后直接搜索。失败不产生半份档案、不跳转，重建保留草稿；连接条件不足仍保留已确认信息。已有同编号登记保持幂等。
2. **首页直接呈现连接结果。** 冷启动恢复完整档案后，仅在前台、已授权且蓝牙/必要定位可用时自动连接一次。未满足条件显示恢复动作；失败后用户直接重试。选择设备成功保存后回首页连接，三项设备信息未齐时保持查询中；取消、返回、关闭弹窗、页面重建不会自动重复。设备详情提供更换戒指，选择后沿用同一可靠保存路径。
3. **按状态提供一个主要动作。** 等待时防重复；超时直接重试；权限/蓝牙条件不足进入对应设置；已有记录或正在采集说明问题并提供详情；全部检查成功自动呈现结果。
4. **就地修改位置。** 选择即写入，成功才更新已确认值；取消不变，同值不重复写。写失败保留原值并可重试，保存中防重复。
5. **保留必要指引。** 当前步骤、字段名、真实状态、异常处理保留；技术信息按需展开。清零、等待开始确认、站定停止及稳定读数提示在未来对应操作时呈现，数据含义保持总纲约定。
6. **复测后交付。** 单元测试、Android导航/文件测试、Debug构建、实际输入/返回/重开和连接检查；设备条件不足的项单列。原位安装保留既有档案。

4. **隔离与审查。** 演示档案、session、文件与任务队列独立；实际BLE命令与实验云盘请求均为0，正式目录保持原样。检查退出/重开与待处理任务不会切入真实后端。独立审查关注状态来源、保存及隔离，再执行B23、构建和模拟器操作。
5. **交付明确。** 提供实际APK、复现步骤及运行页面，标明已实现的软件行为、模拟边界、真实设备已验证项和剩余工作。完成后接T2b.2/T2c/T2d真实本地闭环；仅在影响任务理解或数据正确时返修界面。

### 下一项：一段真实数据留在手机

复用本轮页面、CollectionFlow意图接口、请求协调器和扩展账本。按以下依赖完成一个真实本地闭环，内部步骤可分别验证、提交：

1. 建立真实采集owner与前台服务，由它唯一持有BLE；准备页移交连接，采集页只订阅状态。用替身验证切页/后台、进程恢复及迟到回调隔离；不把演示设备UUID关联机制用于真实协议。
2. 接入实际STATUS/LIST和停止、参考保存出口，持久设备关联证据；缺乏明确归属时保留待核对。先只读核对指定设备基线及无新实验待保存记录；停止、参考保存与第3步原始数据保全出口均就绪后，再受控短采。如固件证据不满足保守判据，报告实测差异并调整技术适配。
3. 按已确认设备记录接通Flash/rfbin下载与恢复，保留临时原始文件，核对完整LIST、CRC/SHA与文件范围后才释放保护。共享账本当前只核验调用方提供的文件清单，实际设备记录是否完整由下载适配器证明。
4. 验收真机短时路径：开始确认、后台采集、停止、读数先保存、对应原始文件落盘、重开恢复；记录请求/确认/样本边界及限制。UI只根据这些真实结果呈现。该项完成后进入T2e/T3云盘与研究端闭环。

前台服务、真实采集和下载均尚未验收；物理设备操作集中安排。Q01/Q02不阻塞上述正常路径，计步器型号/佩戴方式及后端读取配置按对应验收前置补齐。

## 4. 采集接入的复用边界与迁移顺序

旧 RingCaptureService 同时管理采集、身份和上传，不能把准备 Activity 直接绑定过去。源码核对发现：旧路径在发送START后建立身份、收到任意collecting状态自动接管、用下载完成时刻补结束时间。这些行为与新session契约冲突。

T2b实施前先说明并审阅以下技术迁移：由独立协调器管理持久请求和设备对应，前台服务独占既有RingBleClient；Activity只发用户意图和显示状态。先完成替身测试，再接服务/页面；原版服务与接口保留，独立入口逐段切换到经过验证的新路径。避免准备和采集两套控制器同时连接同一戒指。该方案调整职责，保持现有协议与文件格式；若进一步改变实验流程或数据语义，先确认需求。

具体边界：

- START/STOP返回成功只代表命令入队；状态展示依赖对应设备证据和账本成功写入。一次STATUS不能单独证明新记录归属。
- 对START结果不明的恢复先查询；设备重启、未知归属或边界丢失保持异常，不以手机当前时间补造真实边界。
- LIST按已确认的记录身份匹配，不能自动选“最新记录”归入当前被试。
- 停止确认、参考确认、下载完成分别持久；文件清单和后续边界证据可补齐，参考确认锁定不阻止处理字段更新。
- HealthFlashDownload转换失败后的临时文件删除、UploadSessionStore非原子回退为接入时的重点审查项。唯一未保全信号应继续留存。
- 旧实时IMU/PPG同步文件写入受主线程回调调整影响；若启用实时流，先将I/O移到有序后台并验关闭/落盘，准备查询通过不代表采集性能通过。
- 新旧包采用明确版本分路。暂定容器v2/rfbin v2，新增step_schema_version=1与daily_activity_v2；实现前同步端侧和Python契约，避免旧白名单拒收。

## 5. 实物前置条件与验收门禁

指定约5MB旧记录已获准无需保留，无需新增恢复/迁移任务。现有证据仅证明设备当时空闲并报告记录量；仓库没有固件实现或证明START覆盖方式的资料。新采集前核对同一设备、空闲状态及无新实验待保存记录，保留STATUS/LIST基线，再受控执行单次START、查询确认、STOP和LIST，结合原始片段核对新旧记录边界。此授权只覆盖指定旧记录；新数据继续受防丢失保护。

真实采集验证需要：手机解锁并允许系统权限、指定戒指有电、计步器型号与统一佩戴方式、可核对的云盘读取配置。手机上传配置与Python读取位置必须一致。真实链接、账号、凭据和绝对本机路径留在本地配置。

长时验证按短时、约1小时、数小时逐级推进，再依据证据探索接近一天；这些是测试梯度，不是软件限制。每一级核对电量、存储增长/满后行为、样本覆盖、手机下载与峰值空间、上传/解码耗时和恢复。软件超时、时间窗口和解压限额不能当作设备支持时长。跨午夜只有一个参考总数时保持整段，不拆分两日真值。

进入小规模试用前须同时满足：

- 一名按指导准备的测试者独立完成真实采集，混合活动只填写一个同时间段总数。
- 有效零步、缺失、不可靠记录可分辨，保存/重启后保持一致。
- 手机、manifest、云盘文件和后端记录逐字段对应，原始文件/派生CSV可追溯。
- 重启、断连、下载中断、上传失败/回执丢失的关键恢复路径通过，重复导入不重复计数。
- 已验证时长、设备/固件与未覆盖条件明确；再确定人数、周期和质量阈值。
